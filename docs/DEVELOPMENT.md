# Запуск и сборка из исходников

## Что понадобится

- Node.js 22.12 или новее, вместе с npm.
- Git для клонирования репозитория.
- Для Windows-установщика — Windows 10/11 x64. Linux и macOS собираются на соответствующих системах.

## Запуск

```sh
git clone https://github.com/whydoyouseegit/repomap.git
cd repomap
npm ci
npm start
```

При первой установке зависимостей нужен интернет. После этого локальные проекты можно анализировать офлайн. На Windows также можно запустить `start.bat`.

## Проверки

```sh
npm test
```

Проверяются разбор символов, разрешение импортов и алиасов, работа с временными папками, исключения и проверка Git-ссылок.

`scripts/smoke.cjs` проверяет настоящий интерфейс Electron. `scripts/main-smoke.cjs` проверяет IPC и worker упакованной программы. Они предназначены для разработческой проверки; обычному пользователю их запускать не нужно.

## Собрать установщик для Windows

На Windows выполни:

```sh
npm ci
npm run build:win
```

В `release/` появится **`Repo-Map-Setup-0.1.3-x64.exe`**. Это один автономный NSIS-установщик со всеми файлами программы внутри. Он устанавливает приложение в выбранную папку, создаёт ярлыки и добавляет удаление через настройки Windows.

При сборке автоматически проверяются встроенная иконка EXE, версия, название приложения и иконки в ресурсах. Если вместо своей иконки попадёт стандартная Electron, сборка завершится ошибкой.

Цифровая подпись настраивается отдельно: [Windows signing](WINDOWS_SIGNING.md).

## Исходники и контрольные суммы

```sh
npm run pack:source
npm run checksums
```

Архив исходников создаётся из текущего **Git-коммита**, без `node_modules`, результатов сборки и незакоммиченных изменений. Перед выпуском сохрани нужные изменения в Git.

## Linux и macOS

```sh
npm run build:linux
npm run build:mac
```

Linux получает AppImage, macOS — ZIP. Эти команды не создают Windows-установщик.

## Как публикуется релиз

1. Измени версию в `package.json`, обнови `package-lock.json` и подписи версии в интерфейсе.
2. Добавь описание выпуска в `docs/releases/v<версия>.md`.
3. Открой PR. GitHub Actions проверит тесты и сборки. Windows дополнительно проверит тихую установку, запуск приложения и удаление.
4. После слияния в `main` workflow **Publish Windows release** соберёт установщик, архив исходников, общий релиз-пак и SHA-256. Затем создаст тег и GitHub Release.

Если релиз с этой версией уже существует, публикация пропускается. Готовые файлы не перезаписываются. Для нового выпуска нужен новый номер версии. Workflow также можно запустить вручную из Actions.

## Где что лежит

| Папка | Содержимое |
| --- | --- |
| `electron/` | Главное окно, Git, IPC, анализатор и отдельный поток анализа |
| `src/` | Интерфейс, трёхмерная карта и встроенный демопроект |
| `src/assets/` | Иконки приложения |
| `docs/` | Руководства и баннер README |
| `examples/` | Проект для демонстрации и проверок |
| `tests/` | Тесты анализатора |
| `scripts/` | Проверки, упаковка и тест установщика |
| `.github/workflows/` | CI и публикация релиза |

Технологии: Electron, Node.js, TypeScript Compiler API и Canvas 2D с перспективной 3D-проекцией. Серверной части нет.
