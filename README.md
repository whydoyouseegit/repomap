# Repo Map

Создатель — **/home/whydoyousee** · [GitHub](https://github.com/whydoyouseegit).

Локальная программа для исследования кода в виде трёхмерной вселенной файлов, классов и функций.

Чёрно-белый терминальный интерфейс, вращающееся облако точек, дерево проекта и инспектор кода. Работает отдельным окном. Браузер и сервер не нужны.

## Запуск готовой программы — Windows x64

1. Распакуйте **весь** архив `Repo-Map-Windows-x64.zip` в отдельную папку.
2. Запустите `Repo Map.exe`. Соседние файлы и папки нужны для работы.
3. Нажмите **Открыть папку**, чтобы выбрать локальный проект, либо **Git-ссылка** для клонирования.

Node.js для готовой программы не требуется. Git нужен только для клонирования. Локальная папка анализируется без интернета. Сборка предназначена для современных 64-битных Windows 10/11; на реальном Windows-компьютере пока не проверена. Цифровой подписи у этой версии нет.

При первом запуске открыт встроенный демонстрационный проект `orbital-engine`. Его метка **DEMO** исчезнет после открытия вашего проекта.

## Windows SmartScreen и издатель

Надпись «Неизвестный издатель» означает отсутствие доверенной Authenticode-подписи. Поле CompanyName и имя автора в Help не заменяют сертификат. Новая неподписанная программа также не имеет репутации SmartScreen. Изменением иконки или названия это не исправляется.

Исходники позволяют собрать программу с сертификатом: принудительное отключение подписи убрано. Для подписанной сборки добавьте в GitHub → Settings → Secrets and variables → Actions:

- `WIN_CSC_LINK` — сертификат PFX в base64 или поддерживаемая electron-builder ссылка на сертификат;
- `WIN_CSC_KEY_PASSWORD` — пароль сертификата.

Затем запустите workflow **Build desktop apps** вручную с включённым **signed_windows**. Этот режим требует сертификат, останавливается при невозможности подписать EXE и проверяет результат через `Get-AuthenticodeSignature`. Локальная команда — `npm run build:win:signed` с теми же переменными окружения. Сертификаты и пароли не добавляйте в репозиторий.

Обычная сборка PR не использует секреты и остаётся неподписанной. Подпись указывает проверенного издателя, но не гарантирует немедленного исчезновения SmartScreen: Microsoft также учитывает репутацию файла и сертификата. Документация: [SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation), [Electron code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing).

Если Проводник показывает старую иконку, распакуйте актуальный архив в новую папку и проверьте в свойствах `Repo Map.exe`, что версия — **0.1.2**. Не копируйте один EXE из архива: рядом нужны ресурсы приложения. Сборка автоматически подтверждает, что новая иконка действительно находится внутри файла.

## Что умеет

- Чтение локальной папки через системный диалог.
- Клонирование HTTPS/SSH Git-ссылок в отдельный локальный кэш; анализируется текущая ветка, история не загружается.
- Сфера проекта и скопления по папкам, вращение, сдвиг, масштаб и пауза.
- Поиск файлов, классов и функций; выбор по дереву и по точкам на карте.
- Инспектор: состав, входящие/исходящие импорты, наследование внутри файла, фрагмент кода с номерами строк.
- Фильтры типов узлов, отображение импортов, обновление проекта, последние проекты.
- Открытие расположения выбранного файла в проводнике.
- Экспорт структуры в JSON **без исходного кода**.
- Анализ в отдельном потоке, прогресс и отмена операции.

Круги — файлы и функции, ромбы — классы и интерфейсы, квадраты — папки. Мелкая пыль вокруг файлов показывает относительный объём кода и не является отдельными файлами. Сплошные направленные линии — импорты, пунктирные — состав. Связи выбранного узла видны автоматически; все импорты включаются отдельным переключателем.

## Точность анализа

**JavaScript / TypeScript / JSX / TSX:** используется AST TypeScript 5.9.3. Выделяются именованные классы, интерфейсы, функции, методы и стрелочные функции в переменных и полях класса. Разбираются `import`, `export ... from`, `require('literal')`, `import('literal')`; разрешаются локальные пути, файлы `index`, подстановка `.js → .ts` и `baseUrl`/`paths` из корневого `tsconfig.json`.

Это карта структуры и импортов, **не полный граф вызовов**. Вычисляемые импорты, анонимные callback-функции, межфайловое наследование и нестандартные алиасы сборщиков не разрешаются. `extends` конфигурации TypeScript пока не раскрывается. Неразрешённые и внешние импорты перечисляются отдельно.

**Python, C/C++, Java, C#, Rust, Go:** предварительное структурное выделение символов по текстовым правилам. Оно может пропустить сложные объявления или дать ложные совпадения; в инспекторе есть пометка «приблизительно». Для C/C++ также разрешаются локальные `#include "file.h"`. Остальные файлы показываются как файлы без разбора символов.

## Ограничения первой версии

- До 6 000 файлов. Если лимит достигнут, программа сообщает, что отображена часть проекта.
- Разбор содержимого: до 768 КиБ на файл и 32 МиБ текста на проект. Предпросмотр: до 80 000 символов файла и до 120 строк за один просмотр.
- Зависимости, результаты сборки и служебные папки (`.git`, `node_modules`, `dist`, `build`, `target`, `vendor`, `.venv` и др.) пропускаются. Символические ссылки не обходятся. `.env*` и распространённые файлы ключей исключены. Правила `.gitignore` пока не читаются.
- Файлы проекта не изменяются и не исполняются. Автоматического обновления карты при изменениях пока нет: используйте **Обновить**.
- Приватные репозитории требуют уже настроенного Git Credential Manager или SSH-ключа и известного ключа сервера. Токены в Git-ссылках не поддерживаются, интерактивный запрос Git отключён.
- Кэш клонов и список последних папок хранятся в пользовательском каталоге приложения. Обычно это `%APPDATA%/repo-map` на Windows. Управления очисткой кэша в интерфейсе пока нет.

## Запуск из исходников

Нужен Node.js 22.12 или новее. Для клонирования репозиториев нужен Git.

```sh
npm ci
npm start
```

Для Windows также есть `start.bat`: устанавливает зависимости при первом запуске и запускает приложение. Сеть нужна при первой установке зависимостей, затем локальные проекты можно изучать офлайн.

## Проверки и сборка

```sh
npm test
npm run build:win
npm run build:linux
npm run build:mac
```

Артефакты появляются в `release/`. Сборку для нужной платформы лучше выполнять на ней. GitHub Actions собирает Windows ZIP, Linux AppImage и macOS ZIP и прикладывает их к запуску workflow. По умолчанию артефакты не подписаны; отдельный режим signed_windows использует настроенный сертификат.

`npm test` проверяет анализ реальных временных папок, принадлежность символов, разрешение импортов и алиасов, пропуск зависимостей и ключей, целостность графа, пустую папку и проверку Git-ссылок.

`scripts/smoke.cjs` открывает настоящий renderer Electron, проверяет демо, поиск, инспектор, код, режимы карты и управление. Пример для Linux без дисплея:

```sh
npx electron --no-sandbox --ozone-platform=headless --ozone-override-screen-size=1800,1200 --headless --disable-gpu scripts/smoke.cjs
```

Флаги отключения sandbox относятся только к контейнерной проверке; обычная программа запускается с sandbox.

## Устройство проекта

```text
electron/    Главное окно, системные диалоги, Git, анализатор и worker
src/         Локальный интерфейс, карта, встроенный демонстрационный граф
examples/    Небольшой проект для проверки анализа
tests/       Проверки анализатора и Git-ссылок
scripts/     Проверка интерфейса Electron
```

Технологии: Electron, Node.js, TypeScript Compiler API, Canvas 2D с собственной перспективной 3D-проекцией. Нет CDN, облачного анализа, телеметрии и серверной части.
